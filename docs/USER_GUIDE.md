# XferBridge 用户指南

## 1. 前置条件

| 组件 | 要求 |
|---|---|
| Minecraft | Java 版 1.20.1，Forge 47.x（建议 47.3.0） |
| 模组 | `xferbridge-1.0.0.jar` 放入 `mods\`（源与目标存档共用同一份模组文件） |
| 外部工具 | Windows + Python 3.11+（官方 python.org 安装版即可，无需第三方库） |
| 工作区 | `%APPDATA%\XferBridge`（工具与模组自动创建） |

> 目标存档所在的启动器建议与外部工具扫描范围一致（工具默认覆盖官方/PCL/HMCL/CurseForge/Prism/MultiMC）。

## 2. 首次运行外部工具

1. 打开命令行执行 `python run.py`（在 `tool\` 目录）。
2. 点「扫描存档」：工具会枚举所有 Java 版存档，列出路径、版本、模组数、
   是否已装 XferBridge。
3. （可选）点「启动 IPC 守护」：后台轮询，处理游戏内发来的请求。

## 3. 游戏内流程

进**源存档**（想带走角色的那个）后：

1. 按 **F9**（或主菜单 / 暂停菜单的「XferBridge」按钮）。
2. **选择目标存档**（列表来自外部工具扫描索引）。
3. **依赖检查**：对比两个存档的模组：
   - 缺失前置/依赖、版本不匹配、冲突、重复、依赖环 全部列出；
   - 有缺失模组 → 弹出「是否为目标存档安装缺失模组」。
     - **否** → 停止跨越，返回上一步；
     - **是** → 先备份目标存档，再选：
       - **引导安装**：列出缺失模组清单及下载链接（浏览器打开）；
       - **自动安装**：先出示免责声明 → 勾选「我已阅读并同意」→ 输入随机验证码 →
         点「开始自动下载」→ 下载到目标 `mods\.staging`（SHA1/MD5 校验）→
         提示「缺失模组已下载完毕，需要重启游戏才能生效，是否现在重启？」。
4. **配置对比**：只列共存模组的配置文件（缺失模组的配置直接进隔离区），
   每项可选「用源覆盖」，**默认保留目标配置**；替换前目标 config 文件夹整包备份。
5. **物品映射**：提示「有 X 件物品因目标存档缺少模组将暂存于隔离区/虚拟背包，是否继续？」；
   同名不同 ID 可手动填替换 registry（如 `mod:item_new`）。
6. 迁移执行（由外部工具完成打包/写入/校验），完成后显示结果与重启提示。

## 4. 隔离区 / 虚拟背包

- 迁移时，目标存档当时缺少对应模组的物品不会写入玩家背包，而是存入隔离区
  （每存档一个 JSON + 游戏内 `QuarantineStore` 特殊数据包）。
- 进入**目标存档** → F9 →「隔离背包」：
  - 逐件/全部放回（对应模组安装后即可还原）；
  - 导出：zip 压缩包（外部工具）或 Base64 字符串，可分享给其他机器。

## 5. 备份与回滚

外部工具提供：

- **全量备份**：跨越操作发生前自动执行（含独立 config 备份）。
- **增量备份**：玩家退出世界 / 跨越前 / 手动保存时触发（按文件哈希对比，只存变化部分）。
- **一键回滚**：备份列表中选中任意备份点 → 恢复。回滚前自动把当前状态存成新备份
  （链式回滚），可反复回滚。

## 6. 常见问题

- **游戏内列表是空的**：先在外边工具点「扫描存档」并启动 IPC 守护；确认工作区一致。
- **目标存档缺少模组但选择了否**：不会写入任何数据，可安全返回上一步。
- **物品放不回来**：对应模组尚未安装/未重启；安装后重启即可放回。
- **构建失败**：见 README「构建模组」，确保 JDK 17、网络可达 maven.minecraftforge.net。
